# API contracts

Config: Initial (defined nonempty state string, <=128 bytes); States (plain dictionary of state definitions); Context (optional application-owned value); OnChanged(context, old, new, payload) (optional synchronous notification). State definitions accept Transitions (target -> true or guard function), Update(context, dt, state) (optional synchronous function returning target or nil). Unknown fields, unknown destinations and explicit self edges are rejected at construction. State graph is copied/frozen; Context and payload are intentionally application-owned references, not serialized or validated.

Transition returns true when committed, false and a code when rejected. Guard(context, old, target, payload) must return exactly true; false/nil/other values reject. Guard exceptions/yields return false, CALLBACK_ERROR/CALLBACK_YIELDED; error detail may be returned as third value. OnChanged runs after commit; its exception/yield returns **true**, CALLBACK_ERROR/CALLBACK_YIELDED, optional detail. Do not blindly retry a committed transition. Callback side effects cannot be rolled back. No initial notification or destruction notification.

CanTransition checks graph only; guards may change. Transition to same state returns false, SAME_STATE. Unknown state returns UNKNOWN_STATE. Missing edge returns TRANSITION_NOT_ALLOWED. Step rejects nonfinite/negative dt, calls the current state's Update if present, and applies its returned target through the same guard pipeline; nil means successful no-op. No automatic timers or updates.

Token is a unique frozen table identity, replaced on each committed transition, including leaving and returning to the same state. Tokens are local, not serializable IDs. IsCurrent returns false after Destroy. TransitionIfCurrent checks token and transition in one synchronous operation. Never use tokens as a distributed lock. For yielding game work, capture a token before yielding and call TransitionIfCurrent afterwards; check IsCurrent before other side effects.

Reentrant mutations on the same machine return BUSY, including Destroy and Step; read methods remain available. Callback threads that suspend are cancelled/closed on a best-effort basis; callers must not schedule detached side effects inside guards. Callbacks must terminate, not yield, and use server-owned state for authoritative gameplay. No protection against infinite loops or external application side effects. Distinct machines can be used independently.

Destroy is idempotent, releases references to state definitions, context and notification, and invalidates all tokens. GetState/Token return nil, DESTROYED afterwards; mutating methods return false, DESTROYED. Caller owns Heartbeat/other connections and must disconnect them. No registry or tasks created by the module itself.
